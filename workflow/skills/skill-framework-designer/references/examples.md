# Worked runtime skill contracts

These examples use an illustrative platform with governed actions. Adapt tool names, grants, and lifecycle policy to the assigned port.

| Contract field | Reschedule an appointment | Create a personal reminder |
| --- | --- | --- |
| **Purpose and activation** | Change an existing appointment when the user requests a new time. Route a new booking elsewhere. | Schedule a one-time personal reminder when the user asks to be reminded. Route medical scheduling to the appropriate service. |
| **Input schema** | Draft fields `appointment_ref: string?`, `preferred_window: TimeRange?`, `slot_ref: string?`. A proposal requires a validated appointment and slot reference. | Draft fields `message: string?`, `local_time: datetime?`. A proposal requires nonempty text and an unambiguous future timestamp with time zone. |
| **Output schema** | Intermediate question, available slots, or pending action reference. Terminal outcome `rescheduled | cancelled | expired | failed`, with appointment reference and new time required for success. | Intermediate question or pending action reference. Terminal outcome `created | cancelled | expired | failed`, with reminder reference and due time required for success. |
| **Required context** | Scoped appointment records, trusted session context, and user time zone. | Trusted session context, platform clock, and user time zone. |
| **Conversation and questions** | Resolve the appointment and preferred window. Ask “Which appointment?” when ambiguous and “Which of these times works?” after lookup. Present fresh options if a slot disappears. | Ask “What should I remind you about?” or “When should I remind you?” for missing details. Clarify ambiguous local times before proposing creation. |
| **State transitions** | Collect details → check availability → await slot choice → submit proposal → await required confirmation or action result → terminal outcome. Return to slot selection when a choice goes stale. | Collect details → submit proposal → await required confirmation or action result → terminal outcome. A revised reminder before submission returns to validation. |
| **Tools and authorization** | Scoped appointment lookup and availability queries, then a governed reschedule proposal with the selected slot. The host obtains any required confirmation and executes. | Platform clock and a governed reminder creation proposal. The host obtains any required confirmation and schedules delivery. |
| **Errors** | Report lookup denial without exposing records. Recheck a stale slot. Resolve uncertain execution through action status before another proposal. | Re-ask for an invalid time. Report a denial or expired confirmation. Check the action status on timeout and reuse the logical action identity when retry is permitted. |
| **Cancellation and interruption** | Cancel an unsubmitted draft. Follow host policy for unrelated requests and pending actions. A committed reschedule needs a separate permitted change. | Cancel an unsubmitted draft. Follow host policy for unrelated requests and pending actions. Cancelling a created reminder is a separate operation. |
| **Checkpoint and resume** | Save stage, appointment reference, preferred window, offered slot references and expiry, expected reply, and action reference when present. On reload, validate the selected slot or check the pending action. | Save stage, validated text and time, expected reply, and action reference when present. On reload, ask only for missing data, revalidate the due time, or check the pending action. |
| **Completion criteria** | Report success after a confirmed result provides the updated appointment time. Record cancellation, expiry, or failure as a distinct result. | Report success after a confirmed creation result provides the reminder reference and due time. Report cancellation, expiry, or failure distinctly. |
| **Independent tests** | Stub appointment lookup, availability, and actions. Reload while awaiting slot choice, test stale slots and interrupted dialogue, and replay an action result to verify a single effective reschedule. | Fix the clock and stub the action service. Reload while waiting for the time, test ambiguous dates and cancellation, and replay a reply to verify a single effective creation. |
