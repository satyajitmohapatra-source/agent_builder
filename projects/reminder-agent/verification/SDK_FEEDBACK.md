# Chotu SDK feedback from the Port 2 reminder prototype

**Evaluated:** SDK `v0.3.0-dev.9` (`4f5f95c`), draft contract `0.2`, Port 2 (Daily Life). Offline SDK conformance passed 12/12 checks, and four focused harness tests passed. The evaluation used the SDK mock host. Production reminder persistence and scheduled delivery were outside the test run. [Evaluation results](status.md)

| Priority | Finding | Suggested change and acceptance check |
| --- | --- | --- |
| **P1 · SDK API gap** | Port 2 can request `reminder.read`, but the SDK's `DataService` has no typed personal-reminder read. The capability spec already tracks typed reads as dependent on the domain service. This blocks listing and resolving a cancellation target through the SDK. [Scope catalog](/home/user/projects/chotu-sdk/spec/CAPABILITIES.md:58) · [DataService](/home/user/projects/chotu-sdk/src/chotu_agent_sdk/services.py:65) | Publish a scoped upcoming-reminder query and a typed result containing a stable reminder reference and the fields needed for display and selection. Verify due-time ordering, empty results, access denial, and isolation across users. |
| **P1 · SDK contract gap with a host dependency** | Create and cancel action kinds are declared. The generic proposal accepts a parameter dictionary, and the evaluated SDK provides no typed reminder payloads or result contract. The inspected host test expects `SERVICE_UNAVAILABLE` for create pending the reminder domain service. [Action catalog](/home/user/projects/chotu-sdk/spec/CAPABILITIES.md:84) · [Proposal model](/home/user/projects/chotu-sdk/src/chotu_agent_sdk/models.py:282) · [Host test](/home/user/projects/Chotu/backend/tests/test_gate.py:186) | Agree on and document create/cancel payloads, validation, confirmation readbacks, and result fields with the host owner. Add shared fixtures proving that the same proposal works in the mock and host, including stale cancellation targets and duplicate submissions. |
| **P1 · Mock fidelity** | The offline mock returns a generic recorded result for reminder creation. The test confirms one approved call reached the mock domain, so it can pass without exercising a stored reminder, a later read, cancellation, or delivery. [Mock domain](/home/user/projects/chotu-sdk/src/chotu_agent_sdk/testing/domain.py:45) | Add a reminder-specific mock or contract fixture that validates and stores a reminder, then exposes it through the same typed read. Use a fake clock to verify one scheduled delivery attempt, and test cancellation and duplicate creation. Make unsupported kinds return an explicit unavailable result in contract-level tests. |
| **P2 · Action recovery ergonomics** | The documented status lookup needs an action ID, which the agent may lack if the initial submission times out before returning a result. The prototype therefore keeps an unknown state. The SDK already documents deduplication by proposal key. The missing piece is a clear recovery procedure for this case. [ActionService](/home/user/projects/chotu-sdk/src/chotu_agent_sdk/services.py:96) · [Prototype timeout path](../port_2/agent.py:115) | Document and test exact-proposal replay with the original key after a lost response, including restart and changed-payload behavior. If replay cannot safely recover an existing action in every supported host, provide a scoped lookup by proposal key. The recovery test should return the original outcome with one effective side effect. |
| **P2 · Conformance coverage reporting** | The CLI reported PASS for the 12 checks it ran. The contract describes 20 boxes, and the changelog identifies 13–20 as planned work. This makes the report easy to mistake for coverage of the entire draft contract. [Conformance result](port-2-conformance.json) · [Contract checklist](/home/user/projects/chotu-sdk/spec/SPEC.md:446) · [Changelog](/home/user/projects/chotu-sdk/CHANGELOG.md:202) | Report implemented, passed, failed, and unrun contract checks explicitly, along with the contract version and offline mode. Verify that a 12-check report clearly exposes the eight checks outside its coverage. |

The host owns persistent reminder writes and scheduled delivery. Those capabilities need host integration tests before the reminder agent can be accepted. The prototype's limited English date parser and missing list/cancel implementation are agent limitations and were excluded from SDK defect counts.
